# 実装計画

## 1. 安全なエラーハンドリングと終了処理
- 独自例外 `AutomationError` を定義します。
  - `class AutomationError(Exception): pass`
- `find_single_csv` や他のエラー判定箇所において、`sys.exit(1)` を直接呼ぶのではなく、`AutomationError` を発生させます。
- `main()` の `except Exception as e:` 内で、例外が `AutomationError` であるか他の汎用例外であるかに関わらず、発生したエラーを `error.log` に `traceback.format_exc()` で書き込みます。
- メッセージダイアログを、非エンジニア向けに「[発生した状況] \n\n[対処方法]」というフォーマットで日本語に統一し、専門用語を排除します。

## 2. 完成版Excelのロック状態（開きっぱなし）への対応
- `RETAIL_完成版.xlsx` の上書き保存、または削除時に発生しうる `PermissionError` をキャッチします。
- メッセージ：
  - 状況：完成版Excel（RETAIL_完成版.xlsx）が開いたままになっています。
  - 対処方法：Excelを閉じてから再実行してください。

## 3. 列インデックス依存の排除
- `step2_python_direct_merge` 内での列操作が、元の列順序に依存しないようにします。
- 動的な列インデックス解決関数を導入します：
  - 指定したヘッダー名を持つ列インデックスを走査・解決します。
- 列操作を以下のように書き換えます：
  - `ws_order` 内で列削除する際、"商品コード" や "商品名" などのヘッダー列がどこにあるかを検索し、その列番号を動的に使用します。
  - 計算式設定ループの対象列も、店舗名（名古屋, TOKYO など）のヘッダーが位置する列を動的に解決するコードに修正します。

## 4. 1セル書き込みのボトルネック解消
- `ws_retail (AW1:BY10000)` や `ws_order (AR1:BA10000)` などの不要セルクリア処理（合計39万回のループ）をリファクタリングします。
- ループによる1セルごとの None 代入を止め、シートの実際の最終行（または妥当なクリア範囲）を検出した上で、一括で処理するか、あるいは `ws.delete_rows` や特定の範囲のセルに対してのみクリアを行います。

## 5. マニュアル (README.md) の完全同期
- プログラムが画面表示および `error.log` に出力する日本語エラーメッセージと、`README.md` のトラブルシューティング項目を同期します。
- `README.md` 内に、今回改修されたエラーメッセージの具体的な説明と対処方法を加筆します。
