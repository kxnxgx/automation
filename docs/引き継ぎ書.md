# 出荷明細・売上集計自動化システム 引き継ぎ書

本ドキュメントは、出荷明細・売上集計自動化システムの業務運用者およびシステム保守・開発担当者向けの総合引き継ぎ書です。

---

## 1. システム概要と業務目的

### 概要
本システムは、日々の売上データ（店舗売上・ZOZO・OIOI・自社EC）および出荷関連データ（出荷予定振分、HUTTE出荷指示、特価在庫等）を全自動で集計・名寄せ・検証し、ブランド別（FRV, TEN, HWG）の出荷用集計表（Excelファイル）を作成するシステムです。

### 導入効果・特徴
- **ワンクリック自動化**: `実行.bat` を実行するだけで、3ブランド分のExcelファイルが数秒〜十数秒で完成します。
- **誤発注防止機能**: 確保在庫が不足している商品は、自動的に全チャネルの売上数値を「0」化し、過剰出荷や重複発注を防ぎます。
- **動的レイアウト自動追従**: CSVの店舗数増減や列ギャップ（gap1, gap2, gap3）を自動判定し、Excelの列レイアウト崩れやズレを防止します。
- **文字化け・指数表記防止**: 数字のみで構成された商品コードがExcel上で `1.23E+11` などの指数表記に化ける現象を防ぐため、明示的に数値書式（`0`）を適用します。
- **自動アーカイブ**: 正常終了時に `input` フォルダ内の使用済みCSVを日時別フォルダ（`archive/`）へ自動移動します。

## 3. 日常運用フロー（運用担当者向け）

### 手順1: ファイルの準備
全ブランド（FRV, tennen, HANWAG）の以下の各種CSV/Excelファイルを `input` フォルダに保存します。
※ファイル内でブランドが混在していても、プログラムが自動で判別・抽出します。

| ファイル種別 | ファイル名パターン例 | 必須/任意 | 備考 |
|---|---|---|---|
| 出荷予定振分 | `出荷予定振分.csv` | **必須** | ベースとなる出荷指示データ |
| 店舗売上 | `営業日付別売上分析.csv` | **必須** | 直営店舗の売上実績データ |
| ZOZO売上 | `卸売上明細.csv` | **必須** | ZOZO売上明細 |
| OIOI売上 | `卸売上明細 (1).csv` | **必須** | OIOI（丸井）売上明細 |
| 自社EC売上 | `order_20260601.csv` | **必須** | `order_` で始まるEC注文明細 |
| HUTTE指示 | `★出荷指示フォーマット【20260705】hutte.xlsx` | 任意 | HUTTEの個別指示データ |
| ZOZO/OIOIマスタ | `商品マスタ-ZOZO-OlOl.xlsx` | 任意 | 商品マスタ補助データ |
| 特価在庫 | `2026特価在庫.xlsx` | 任意 | 特価在庫情報 |

### 手順2: 自動処理の実行
1. `output` フォルダ内の同名Excelファイル（例: `20260601 RETAIL FRV.xlsx` 等）がExcelで開かれていないことを確認します。
2. `実行.bat` をダブルクリックします。
3. 黒い画面（コマンドプロンプト）が立ち上がり、FRV → tennen → HANWAG の順に全自動処理が実行されます。
4. 画面上に `[OK] すべて一致しています！` および `処理が正常に完了しました！` が表示されたら終了です。
5. 入力データは `archive/YYYYMMDD_HHMMSS/` へ自動移動されます。

## 4. システム内部仕様（保守・開発担当者向け）

### (1) 店舗構造の動的解析ロジック (`utils.py: parse_csv_store_structure`)
`出荷予定振分.csv` のヘッダー行を解析し、列構成を動的に検出します。
- `N`: 店舗数
- `gap1`: BULK店舗エリアと在庫エリア間の空白列数
- `gap2`: 在庫エリアとORDERエリア間の空白列数
- `gap3`: ORDERエリア（出荷指示数）と出荷予定日列間の空白列数（例: BJ〜BP列の7列）

`generate_sheets.py` では検出された `gap3` を使用して、出荷予定日列の絶対位置を `retail_date_col = retail_col_start + N + gap3` と動的に計算し、`gap3` エリアの空白列を自動的に非表示 (`hidden = True`) に設定します。

### (2) 誤発注防止ロジック（売上ゼロ化）
店舗・各チャネルからの総売上要求に対し、確保可能枠（RETAIL確保およびBULK確保）が不足している場合、該当商品行の全チャネル（ZOZO, OIOI, EC, 店舗）の売上指示数を強制的に `0` に上書きします。
これにより、在庫がない状態で誤って出荷指示が出される事故を防止します。

### (3) 数値書式設定（文字化け・指数表記対策）
Pythonで生成するExcelファイルの `order` シート A列（商品コード）および `RETAIL` シート D列（商品コード）に対し、`number_format = '0'` を明示的に設定します。これにより、数字のみで構成されたJANコードや品番が `1.21E+11` などと破損するのを防ぎます。

### (4) データの整合性自動検証 (`verify_pipeline`)
`verify_all.py` 等を実行すると、元CSVから直接計算した期待値と、生成されたExcelファイルの全セルの数値を突き合わせ、合計値だけでなくセル単位（商品×チャネル）での完全一致を自動検証します。

## 5. トラブルシューティングガイド

| 現象・エラーメッセージ | 原因 | 対処方法 |
|---|---|---|
| **完成版Excelファイルが開いたままです** | 出力先のExcelファイルがExcel等で開かれている | 開いているExcelファイルを閉じてから再度実行する |
| **必要なCSVファイルが見つかりません** | `input` フォルダに必要なファイルがない | 必要なCSVファイルを `input` フォルダに配置する |
| **同じ種類のCSVファイルが複数あります** | `input` フォルダに同種のファイルが複数入っている | 最新のファイル1つだけを残し、他を削除・退避する |
| **数値が過去数ヶ月分合算されて巨大になる** | CSVをダウンロードする際、全期間指定になっている | システムからダウンロードする際「対象日（1日分）」を指定して再出力する |
