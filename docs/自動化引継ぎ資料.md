# 出荷明細作成 自動化システム 開発者向け引継ぎ資料

## 1. プロジェクト概要
- **目的**: 毎日の出荷予定振分データ、および各チャネル（店舗売上、ZOZO、OIOI、自社EC、HUTTE、特価等）の売上・出荷データを集計・マージし、出荷用の集計表（Excelファイル）を全自動で生成する。
- **実行環境**: Windows, Python 3.14 (純粋なPythonライブラリ `openpyxl` および `pandas` で動作し、Excel本体やwin32com等のインストールは不要)
- **主要な機能**:
  - 各種売上CSV/Excelファイルの自動名寄せ・名寄せ集計
  - ブランド別（FRV, TEN, HWG）の厳格な商品・売上データフィルタリング
  - 店舗数の増減に自動追従する「動的列レイアウト解析」
  - 確保枠不足時における自動売上ゼロ化（誤発注防止ロジック）
  - 生成されたExcelデータのデータインテグリティ検証（データ突き合わせ）

## 2. システム構成とモジュール設計

保守性と拡張性を高めるため、モノリシックだった共通ロジックを5つのモジュールに分割しています。

```text
c:\Users\kesuzuki\Desktop\出荷表自動化\
├── config.py                 # 【設定】ブランド設定 (BrandConfig) やエラー定義
├── utils.py                  # 【共通】共通関数 (ブランド判定、ファイル検索、店舗構造解析等)
├── data_loader.py            # 【データ読込】各チャネル (店舗, ZOZO, OIOI, EC, HUTTE, 特価) の集計処理
├── generate_sheets.py        # 【Excel処理】RETAIL/orderシートの構築、マージ、数式設定、書式適用
└── automation_core.py        # 【窓口】メイン制御および検証 (verify_pipeline)、後方互換用再エクスポート
```

### 後方互換性（ファサードパターン）の担保
各ブランド個別の実行スクリプト (`run_automation.py` 等) や検証スクリプト (`verify_all.py` 等) は、歴史的経緯から `automation_core.py` から各種クラスや関数を直接インポートしています。
これらを変更せずに動作させるため、新 `automation_core.py` は各モジュールで定義された以下の主要シンボルをインポートし、そのまま外部へ再エクスポートする構造（ファサード）を採用しています。

```python
# automation_core.py での再エクスポート例
from config import BrandConfig, AutomationError, BRAND_FRV, BRAND_TEN, BRAND_HWG
from generate_sheets import step1_create_retail_wb, step2_python_direct_merge
```

## 3. データ処理フロー

### 【手順1】 RETAIL シートの作成 (`step1_create_retail_wb`)
1. `input` フォルダから `出荷予定振分*.csv` を自動検出し、`pandas` で読み込む。
2. ブランド設定 (`BrandConfig`) に基づき、対象ブランドの商品行（4列目コード、6列目ブランド名）のみをフィルタリングする。
3. `openpyxl.Workbook` を新規作成し、フィルタされたデータを `RETAIL` シートに書き出す。

### 【手順2】 Python直接集計・マージおよび書式適用 (`step2_python_direct_merge`)
1. **シートの複製と初期化**: `RETAIL` シートをコピーして `order` シートを作成する。
2. **店舗構造の動的解析**: `parse_csv_store_structure` を呼び出し、CSVのヘッダーから以下の情報を動的に取得する。
   - `N`: 店舗数
   - `gap1`: BULK店舗と在庫店舗の間の空白列数
   - `gap2`: 在庫店舗とORDER店舗の間の空白列数
   - `gap3`: ORDER店舗（出荷指示数エリア）と出荷予定日の間の空白列数
   - `store_names`: 店舗名リスト
   - `store_codes`: 店舗コードリスト
3. **不要列の削除**: CSV由来の不要なギャップ列を自動削除し、`確保`, `在庫`, `ORDER`, `過不足` の各エリアの列範囲（開始・終了インデックス）を動的に計算する。
4. **デザインとヘッダー適用**:
   - `確保`, `在庫`, `ORDER`, `過不足` の2行目ヘッダーセルをマージ・彩色する。
   - `csv_store_names` に基づき、`確保`, `在庫`, `ORDER`, `過不足` のすべての3行目セルの店舗名を動的に書き込む（テンプレート依存のない動的対応）。
5. **各売上データのロード**: `data_loader.py` を用いて、ZOZO、OIOI、自社EC、HUTTE、特価などの売上データをメモリ上にロードする。
6. **既存商品の売上マージ**: `order` シートの既存商品行に対し、チャネルごとに集計データを書き込む。
7. **誤発注防止（売上ゼロ化）**: 確保枠（C列=0 かつ D列=0 かつ 過不足残の合計 < 売上合計）の場合、ZOZO・OIOI・EC・店舗すべての売上を `0` に書き換える。
8. **新規（漏れ）商品の追加**: 出荷予定CSVにはないが売上が発生している商品（`leaked_codes`）を検出し、`order` シートおよび `RETAIL` シートの末尾へ動的に行追加し、売上データと数式参照を設定する。
9. **数式および書式の適用**:
   - 過不足列の引き算数式（`=確保-ORDER`）を動的に書き込む。
   - 過不足合計（`SUMIF`）、RETAIL確保、過不足残の数式を `lastRow`（動的最終行）を用いて設定する。
   - 1行目に `SUBTOTAL(9, ...)` の合計数式を設定する。
   - 在庫0のセルを非表示（`None`）にする。
   - `order` シートのA列（商品コード列）および `RETAIL` シートのD列（商品コード列）に数値書式（`number_format = '0'`）を適用し、数字のみの商品コードが文字化け・指数表記化するのを防ぐ。
   - `RETAIL` シートのAW列以降に、`order` シートへの動的な参照数式（`=order!...`）を設定する。
   - 出荷指示数エリアと出荷予定日の間にある `gap3` 列（BJ〜BP列等）を自動非表示 (`hidden = True`) に設定する。
   - 出荷予定日列（`retail_col_start + N + gap3` 列目。例: BQ/69列目）に当日の日付を動的に出力する。

## 4. 開発・改修時の重要設計仕様

引継ぎ先でコードを改修する際は、以下の設計意図と仕様に細心の注意を払ってください。

### ① 店舗数の増減への動的追従
店舗の増減により、`order` シートの列数は常に変動します。そのため、列インデックスのハードコーディング（「31列目がZOZO」など）は厳禁です。
列範囲は `N`（店舗数）を基準とした以下の計算式によってすべて動的に制御されています。
- `確保`: `3` 〜 `N + 4`
- `在庫`: `N + 5` 〜 `2*N + 4`
- `ORDER`: `2*N + 5` 〜 `3*N + 4`
- `過不足`: `3*N + 5` 〜 `4*N + 4`

### ② 外部キーの標準化
CSV上の店舗名・チャネル名と、Excelのヘッダー表示には一部表記のズレ（例: CSVは「丸井web」、Excelは「OIOI」 / CSVは「YSEC」、Excelは「EC」）があります。
これらを正確に名寄せするため、`generate_sheets.py` および `verify_pipeline` 内で、キーを標準化（`OIOI` や `EC` 等）してマッピングを行うロジックが組み込まれています。

### ③ 在庫0の非表示化
Excel表示上、値が `0`（または `0.0` や `"0"`）のセルは、ブック保存前に明示的に `None`（空値）に書き換えることで、画面上でスッキリ見せる仕様になっています。

## 5. データ検証パイプライン (`verify_pipeline`)

生成されたExcelデータの信頼性を保証するため、`automation_core.py` 内に `verify_pipeline` が実装されています。

### 動作プロセス
1. **動的店舗検出**: `parse_csv_store_structure` を用いて、テスト対象Excelの `order` シート内の店舗名を動的に特定する。
2. **元CSVの集計**: 卸売上明細（ZOZO/OIOI）、EC売上、営業日付別売上分析（店舗売上）から、対象ブランドの売上合計値を直接集計する。
3. **売上ゼロ化期待値の算出**: `verify_pipeline` 内でも、Excelと同等の「在庫不足時のゼロ化ロジック」をシミュレートし、最終的にExcelに書き込まれるべき「正解値（期待値）」を計算する。
4. **合計値の照合**: 各チャネルの期待値の合計と、Excelシートの `SUBTOTAL` 経由の実際値を突き合わせる。
5. **商品レベルの差異分析レポート**: 合計値の突き合わせだけでなく、セル単位で期待値と実際値が異なる箇所がないかを走査し、不一致があった場合は該当商品コード・チャネル名・行番号・不一致数値を詳細にコンソールに出力する。
