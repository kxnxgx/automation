# 実装計画書 - Milestone 5 & 6 (管理ドキュメント作成 & 取扱説明書作成)

## 1. 概要
本計画書は、出荷集計自動化システムを実業務で安全かつ円滑に運用・保守するために、管理者向けの「管理ドキュメント」および実務担当者（非技術者）向けの「取扱説明書」を整備する計画を定義します。

## 2. 設計方針

### 2.1 管理ドキュメント（管理者向け）
- **対象読者**: システム管理者、IT部門担当者、後任のエンジニア
- **目的**: システムの全体構造、各ファイルの依存関係、および正常性の検証方法を理解し、将来的な改修やトラブル対応を容易にすること。
- **格納場所**: `C:\Users\kxnxg\antigravity\valiant-oppenheimer\docs\shipment_aggregation_manual\`
- **作成ファイル**:
  - `task.md`: 全体タスクのチェックリストと進捗管理。
  - `implementation_plan.md`: 本ドキュメント。ドキュメント化の設計方針と計画を明記。
  - `walkthrough.md`: 検証結果や運用開始に向けた確認プロセスの報告。

### 2.2 取扱説明書（実務担当者・非技術者向け）
- **対象読者**: 営業事務・出荷管理などの実務担当者（PCの基本操作はできるが、プログラミングやIT用語に不慣れな非エンジニア）
- **目的**: 迷うことなく日々の出荷データの集計作業を完了させ、エラー発生時に自己解決、または的確な一次対処ができるようにすること。
- **格納場所**: `C:\Users\kxnxg\OneDrive\デスクトップ\automation\README.md`
- **表記ルール（非技術者向けトランスレーション）**:
  - 技術用語を徹底的に排除し、日常のオフィス業務で使われる言葉に翻訳します。
    - ✕ スクリプト、プログラムコード、Pythonプログラム ➔ ◯ 集計プログラム、プログラム
    - ✕ パス、ディレクトリ、CWD ➔ ◯ フォルダ、保存場所
    - ✕ 引数、パラメータ ➔ ◯ 設定、指定ルール
    - ✕ スクリプトを実行する、コマンドを叩く ➔ ◯ ダブルクリックする、実行する
    - ✕ 標準出力、コンソール、ターミナル ➔ ◯ 黒い画面、実行画面
    - ✕ 例外、スタックトレース ➔ ◯ エラーログ、エラー時の記録

## 3. 作成プロセスと詳細設計

### Step 1: 管理ドキュメントの構成定義
- `task.md` の作成（進捗チェックリストの明文化）
- `implementation_plan.md` の作成（本設計書）
- `walkthrough.md` の作成（検証済みの動作仕様、入力ファイルの条件、突合ロジックの定義）

### Step 2: 非技術者向け取扱説明書（README.md）の執筆
以下の項目を明確かつ視覚的に分かりやすく整理します。
1. **何ができるようになるか（機能概要）**
   - 手作業での転記・集計を無くし、各種CSVから自動で `RETAIL_完成版.xlsx` を作成すること。
2. **準備するもの（入力CSVファイルの一覧と配置場所）**
   - 必要な5つのCSVファイルの名前パターンと、システムからのダウンロード方法の説明。
     - `出荷予定振分*.csv` (例: 出荷予定振分.csv)
     - `営業日付別売上分析*.csv` (例: 営業日付別売上分析.csv)
     - `卸売上明細.csv` (ZOZO分)
     - `卸売上明細 (1).csv` (OIOI分)
     - `order_*.csv` (EC受注データ)
3. **実行手順**
   - `input` フォルダにファイルを置き、`実行.bat` をダブルクリックするだけの手順。
4. **結果の確認方法**
   - 黒い画面（コマンドプロンプト）の最後に `[OK] すべて一致しています！` と表示されることを確認。
   - 作成された `RETAIL_完成版.xlsx` の確認方法。
5. **トラブルシューティング**
   - 画面がすぐに閉じてしまったりエラーが出たりした際の `error.log` の確認方法。
   - Excelが開きっぱなしになっている場合の「書き込み権限エラー」対策と閉じ方の指示。

### Step 3: 作成ファイルの存在検証と整合性確認
- 作成した各ファイルが指定された絶対パスに正しく作成されているか、文字化けや抜け漏れがないかを実際にプログラム等で読み込んで検証します。
