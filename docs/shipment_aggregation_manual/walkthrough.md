## 3. システム仕様と動作検証内容

### 3.1 データ連携と検証の仕組み
本プログラム（`run_automation.py`）は、実務担当者が `input` フォルダに配置した5種類のCSVファイルからデータを抽出・集計し、テンプレートをベースに `RETAIL_完成版.xlsx` を自動作成します。
その後、`verify_all.py` が自動起動し、以下の突合処理を行って数値の一致を確認します。

| 集計対象 (チャネル) | 元CSVファイル名 (input内) | 突合ロジック (元データ vs 完成Excel) |
| :--- | :--- | :--- |
| **ZOZO** | `卸売上明細.csv` | ブランド名「FRV」「FJALLRAVEN」の「販売数量」合計と、`order`シート AE列(31列目)の合計値の突合 |
| **OIOI** | `卸売上明細 (1).csv` | ブランド名「FRV」「FJALLRAVEN」の「販売数量」合計と、`order`シート AG列(33列目)の合計値の突合 |
| **EC (YSEC)** | `order_*.csv` | 「決済方法」に「キャンセル」を含まず、かつ「注文者」に「店舗客注」を含まない「個数」合計（ただしギフトコード「GIFT」は除く）と、`order`シート AH列(34列目)の合計値の突合 |
| **店舗売上** | `営業日付別売上分析*.csv` | 表記部門名「FRV」「FJALLRAVEN」の「数量」合計を店舗ごとに分類した値と、`order`シートの各店舗列（名古屋: AF列, TOKYO: AI列, 大阪: AJ列, ヒュッテ: AK列, 新宿: AL列, 心斎橋: AM列, 6142: AN列, 玉川: AO列, NODE: AP列, 成田: AQ列）の合計値の突合 |

### 3.2 検証結果の出力仕様
すべての項目で「元CSVの合計値」と「完成Excel（`RETAIL_完成版.xlsx`）の列合計値」が一致した場合、コマンド画面に以下の通り出力されます。
```text
[3] 突き合わせ結果（正解値 vs 実際値）
=======================================================
  ZOZO        : 正解=31  実際=31  [OK]
  OIOI        : 正解=23  実際=23  [OK]
  EC          : 正解=145  実際=145  [OK]
  名古屋      : 正解=12  実際=12  [OK]
  ...
[OK] すべて一致しています！
```
この表示が出れば、転記漏れや二重集計がないことが保証されます。

## 4. トラブルシューティング検証
運用時に発生しやすい問題とその解決策について実機環境での整合性を確認しました。

1. **Excelファイルのロック（書き込み権限エラー）**
   - **事象**: `RETAIL_完成版.xlsx` をExcelで開いたままプログラムを実行すると、保存処理で「Permission Denied」などの書き込み禁止エラーが発生し、プログラムが停止します。
   - **対策**: 取扱説明書に「必ずExcelを閉じてから実行すること」を明記。プログラム側ではエラー発生時に `error.log` へ詳細ログを吐き出し、画面に分かりやすい日本語メッセージを出す仕組みが正常に動作することを確認。
2. **CSVファイルのファイル名ゆれ（ワイルドカード処理）**
   - **事象**: 出荷予定データや店舗売上データの日付が変更され、CSVファイル名が `出荷予定振分_20260705.csv` や `営業日付別売上分析(新).csv` のように揺れるケース。
   - **対策**: プログラム内の `find_single_csv` は部分一致（例：`出荷予定振分` や `営業日付別売上分析`）でファイルを特定する設計になっており、前後に文字が付いていても問題なく検知できることを確認しました。
